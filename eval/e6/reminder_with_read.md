# Напоминание о приёме в клинике

Комплект из двух документов. Часть B — дочерняя спецификация, на которую ссылается раздел интеграции в части A.

---

## Часть A. Новый функционал

### Общие сведения

| Поле | Значение |
| :--- | :--- |
| **Наименование задачи** | Настраиваемый интервал SMS-напоминания о приёме |
| **Продукт** | Кабинет пациента, учебный кейс |
| **Бизнес-процесс** | Информирование пациента о записи |
| **Тип работы** | Новый функционал |
| **Влияние на ИС** | Кабинет пациента, служба расписания, SMS-шлюз |

### Цели
Снизить число неявок за счёт напоминания в удобное пациенту время.

### Архитектура решения
Кабинет пациента → служба профиля пациента. Служба расписания → планировщик напоминаний → SMS-шлюз.

### Дизайн процесса UI
Профиль → Уведомления → Напоминания. На экране отображаются текущий интервал напоминания в часах, поле для нового значения и кнопка «Применить».

### Требования к изменениям

#### Функциональные требования
* **П-1.** Пациент выбирает интервал напоминания: 2, 12, 24 или 48 часов до начала приёма. Значение по умолчанию — 24 часа.
* **П-2.** Кабинет показывает пациенту интервал, который действует сейчас.
* **П-3.** Новый интервал применяется к напоминаниям, которые ещё не отправлены.

### Нефункциональные требования
SMS передаётся в шлюз не позднее пяти минут после наступления расчётного момента напоминания.

### Требования к данным
Хранить идентификатор пациента, интервал в часах и дату изменения интервала.

### Требования к интеграции
Кабинет пациента получает и изменяет интервал через дочерний документ «Интервал напоминаний — REST API».

### Критерии приемки

| Исходные условия | Действие | Ожидаемый результат |
| :--- | :--- | :--- |
| Интервал 24 часа | Пациент открывает экран напоминаний | Отображается значение 24 |
| Интервал 24 часа, приём завтра в 15:00 | Пациент выбирает 2 часа | SMS уходит в 13:00 в день приёма |

## Часть B. REST API

Дочерний документ части A: «Интервал напоминаний — REST API».

### Общие параметры

| Поле | Значение |
| :--- | :--- |
| **Description** | Изменение интервала напоминания |
| **REST type** | PUT |
| **Authorization** | Bearer, сессия пациента |
| **Controller** | ReminderController |
| **Request URL** | `/patients/{patientId}/reminder-interval` |

### Логика работы метода
1. Проверить сессию пациента.
2. Проверить, что `patientId` принадлежит сессии.
3. Проверить, что `hours` входит в список 2, 12, 24, 48.
4. Записать новый интервал вместо прежнего и вернуть `status`.

### Параметры запроса

#### Path-параметры

| Parameter | Format | Mandatory | Description |
| :--- | :--- | :--- | :--- |
| `patientId` | string | Да | Идентификатор пациента |

#### Request body

| Parameter | Format | Mandatory | Description |
| :--- | :--- | :--- | :--- |
| `hours` | integer | Да | Интервал в часах |

### Ответ

| Parameter | Format | Description |
| :--- | :--- | :--- |
| `status` | string | UPDATED |

### Статусы
**200.** Интервал записан.  
**400.** Значение `hours` вне списка.  
**401.** Нет сессии.  
**403.** Пациент не совпадает с сессией.

### Получение действующего интервала

| Поле | Значение |
| :--- | :--- |
| **Description** | Получение действующего интервала напоминания |
| **REST type** | GET |
| **Authorization** | Bearer, сессия пациента |
| **Controller** | ReminderController |
| **Request URL** | `/patients/{patientId}/reminder-interval` |

#### Логика работы получения
1. Проверить сессию пациента и принадлежность `patientId`.
2. Прочитать сохранённый интервал без изменения данных.
3. Если интервал не сохранялся, вернуть значение по умолчанию 24.

#### Ответ получения

| Parameter | Format | Description |
| :--- | :--- | :--- |
| `hours` | integer | Действующий интервал в часах |

#### Статусы получения
**200.** Интервал возвращён.  
**401.** Нет сессии.  
**403.** Пациент не совпадает с сессией.
