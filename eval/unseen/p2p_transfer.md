# Перевод по номеру телефона

## Часть A. Новый функционал

### Общие сведения

| Поле | Значение |
| :--- | :--- |
| **Наименование задачи** | Перевод клиенту другого банка по номеру телефона |
| **Продукт** | Мобильное приложение банка, учебный кейс |
| **Бизнес-процесс** | Переводы физических лиц |
| **Тип работы** | Новый функционал |
| **Влияние на ИС** | Мобильное приложение, сервис переводов, сервис лимитов, платёжный шлюз, SMS-шлюз |

### Цели
Дать клиенту возможность перевести деньги клиенту другого банка, зная только номер телефона получателя.

### Архитектура решения
Мобильное приложение → сервис переводов → сервис лимитов. Сервис переводов → платёжный шлюз → SMS-шлюз.

### Дизайн процесса UI
Платежи → Перевод по номеру. На экране видны поле номера телефона, поле суммы, остаток дневного лимита и кнопка «Перевести». Комиссия показывается до подтверждения.

### Требования к изменениям

#### Функциональные требования
* **П-1.** Клиент переводит от 100 до 500 000 ₸ за одну операцию. Дневной лимит переводов по номеру телефона — 500 000 ₸.
* **П-2.** Дневной лимит считается по календарным суткам по времени Астаны.
* **П-3.** Комиссия составляет 1% от суммы перевода, минимум 100 ₸.
* **П-4.** Крупный перевод требует дополнительного подтверждения одноразовым кодом из SMS.
* **П-5.** Получатель определяется по номеру телефона получателя через платёжный шлюз.

### Sequence Diagram
Мобильное приложение → сервис переводов: создать перевод. Сервис переводов → сервис лимитов: проверить и зарезервировать лимит. Сервис переводов → платёжный шлюз: выполнить перевод. Сервис переводов → SMS-шлюз: передать имя отправителя и сумму перевода получателю.

### Нефункциональные требования
Перевод должен проходить быстро. Сервис лимитов сбрасывает дневные счётчики в 00:00 UTC.

### Требования к данным
Хранить идентификатор клиента, номер телефона получателя, сумму перевода в тенге, комиссию в тенге, дату и время операции и ставку комиссии целым числом процентов.

### Требования к интеграции
Приложение создаёт перевод через дочерний документ «Перевод по номеру — REST API». Повторный запрос с тем же ключом идемпотентности не создаёт второй перевод.

### Критерии приемки

| Исходные условия | Действие | Ожидаемый результат |
| :--- | :--- | :--- |
| Переводов за сутки не было | Перевести 5 000 ₸ | Комиссия 50 ₸, перевод выполнен |
| Переводов за сутки не было | Перевести 600 000 ₸ | Перевод выполнен одной операцией |
| За сутки переведено 450 000 ₸ | Перевести 60 000 ₸ | Перевод отклонён, сообщение о лимите |

## Часть B. REST API

### Создание перевода

| Поле | Значение |
| :--- | :--- |
| **Description** | Создание перевода по номеру телефона |
| **REST type** | POST |
| **Request URL** | `/transfers?otp={code}` |

#### Параметры запроса

| Parameter | Format | Description |
| :--- | :--- | :--- |
| `phone` | string | Номер телефона получателя |
| `amount` | integer | Сумма перевода в тиынах |
| `idempotencyKey` | string | Ключ идемпотентности |
| `otp` | string | Одноразовый код подтверждения передаётся в query-параметре URL |

#### Логика работы метода
1. Проверить сессию клиента.
2. Проверить сумму и дневной лимит.
3. Если ключ идемпотентности уже использован, вернуть результат исходного перевода со статусом 200.
4. Выполнить перевод и вернуть его идентификатор.

#### Статусы
**201.** Перевод создан.  
**400.** Неверная сумма или номер телефона.  
**409.** Повторный запрос с уже использованным ключом идемпотентности.  
**422.** Превышен дневной лимит.
